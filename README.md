# WigsStock · אפליקציית ספירת מלאי (Inventory Barcode Scanner)

אפליקציה קטנה וזריזה לספירת מלאי של ~20,000 פאות מול קובץ **גוגל שיטס**.
כל פאה = ברקוד ייחודי (5 ספרות). העובדות סורקות את הפאות שנמצאות פיזית בחנות,
והאפליקציה עושה **התאמה (reconciliation)** מול הסטטוסים שבשיטס.

**גרסה נוכחית: 1.12.1** · PWA · עובדת אופליין אחרי טעינה ראשונה.

הליבה היא **local-first**: אין צורך בהתקנה, וכל סריקה נשמרת מיידית במכשיר.
בנוסף יש **שכבת ענן אופציונלית** (Cloudflare Worker + D1) שמסנכרנת בין עמדות
בזמן אמת וכותבת חזרה לגיליון — ראו [סנכרון ענן](#סנכרון-ענן-בין-עמדות).

## מה זה עונה

| מצב בשיטס | נסרק פיזית? | קטגוריה | משמעות |
|---|---|---|---|
| `in-stock` | ✅ | **תקין** | קיים כמו שצריך |
| `in-stock` | ❌ | **חסר** | אמור להיות בחנות, לא נמצא (כנראה נמכר/אבד ולא עודכן) |
| כל סטטוס אחר (`sold`, `returned`…) | ✅ | **בחנות אך מסומן אחרת** | פיזית בחנות אבל רשום נמכר → צריך להחזיר ל-`in-stock` |
| לא קיים בשיטס | ✅ | **ברקוד לא מוכר** | נסרק אבל אין לו שורה בקובץ |
| — | 🔁 פעמיים+ | **כפילות** | נסרק יותר מפעם אחת |

## גרסה של קובץ אחד
`wigsstock-app.html` = הכל בקובץ אחד (עיצוב + קוד + ספריית הסריקה). אפשר לשלוח ולפתוח ישירות.
לבנייה מחדש אחרי שינוי: `node build-single.js`.

## אייפון / אנדרואיד — חשוב
- **סורק ברקוד חיצוני (בלוטות'/USB)** — עובד בכל מקום, גם בקובץ מקומי. הכי מהיר ואמין ל-20K פריטים. **מומלץ.**
- **מצלמת הטלפון** — עובדת ב-Safari (אייפון) וב-Chrome (אנדרואיד), אבל **רק כשהאפליקציה מתארחת ב-HTTPS** (למשל GitHub Pages) — לא מקובץ שנפתח מהאחסון המקומי. זו מגבלת אבטחה של הדפדפן, לא של האפליקציה.
- **הקלדה ידנית** — עובדת תמיד.

## איך משתמשים

1. פותחים את `index.html` (או `wigsstock-app.html`) בדפדפן. **להעלאה ל-GitHub Pages**: Settings ← Pages ← מ-branch. מקבלים כתובת https שנפתחת מכל טלפון, וגם אפשר "הוסף למסך הבית" כדי שיראה כמו אפליקציה.
2. **מלאי** → מייצאים מגוגל שיטס ל-CSV (`קובץ ← הורדה ← CSV`) וטוענים. העמודות ברקוד/סטטוס מזוהות אוטומטית.
3. **סריקה** → סורקים. שלוש דרכים:
   - **סורק ברקוד חיצוני** (USB/בלוטות') — הכי מהיר ואמין. סורקים והברקוד נכנס לבד.
   - **מצלמת הטלפון** — כפתור "סרוק עם המצלמה" (Chrome על אנדרואיד).
   - **הקלדה ידנית** + Enter.
   - כל סריקה נותנת משוב מיידי: 🟢 תקין · 🟠 מסומן אחרת · 🔴 לא מוכר · 🔁 כפילות (עם צליל ורטט).
4. **דוח** → סיכום חי + פירוט לכל קטגוריה.
5. **ייצוא** → CSV: דוח מלא / עדכוני סטטוס מוצעים לשיטס / סריקות גולמיות לגיבוי.

**כמה עובדות במקביל:** כל מכשיר סורק לבד, בסוף מייצאים "סריקות גולמיות" וממזגים בלשונית הייצוא.

## בדיקה לפני מלאי אמיתי
`test-barcodes.html` מייצר ברקודי Code 128 להדפסה/מסך, שתואמים ל-`sample-inventory.csv`. ככה בודקים את כל הזרימה עם דוגמה.

## סנכרון ענן בין עמדות

מעבר למצב ה-local-first (סריקה עצמאית + מיזוג ידני בסוף), אפשר להפעיל **סנכרון חי**
כך שכמה עמדות רואות את אותה ספירה בזמן אמת, ובלי מיזוג ידני:

- **Backend:** Cloudflare **Worker + D1** (בתיקיית `worker/`). כל סריקה נשלחת ל-Worker
  ברקע (debounce), עם תור אופליין; כל העמדות מקבלות את המצב המאוחד.
- **קריאת המלאי:** ה-Worker משמש גם proxy לקריאת הגיליון כ-CSV (עוקף CORS).
- **כתיבה חזרה לגיליון:** דרך **Google Apps Script** (`worker/sheets-writeback.gs`) —
  נכתבות עמודות נסרק/תאריך/עמדה (ובכתיבה ידנית גם שם וסטטוס מעודכן), בלי לגעת בעמודות המקוריות.
  יש throttle + cron לכתיבה אוטומטית.

הפעלה: פותחים את האפליקציה → לשונית **מלאי** → **סנכרון ענן**, ומזינים את כתובת ה-Worker
ושם ספירה משותף. הוראות הקמה מלאות של ה-Worker ב-[`worker/README.md`](worker/README.md).

> למה לא לכתוב כל סריקה ישר ל-Sheets API? זה היה איטי ומוגבל בקצב ל-20K פריטים.
> לכן הליבה local-first, והכתיבה לשיטס מרוכזת (throttle/cron/ייצוא) ולא סריקה-בכל-פעם.

## קבצים
- `index.html` · `app.js` · `styles.css` — האפליקציה (frontend)
- `sw.js` · `manifest.webmanifest` · אייקונים — שכבת ה-PWA (אופליין + התקנה למסך הבית)
- `zxing.min.js` — ספריית פענוח הברקוד (מצלמה)
- `wigsstock-app.html` — גרסת קובץ יחיד (הכל inline, נבנית ע"י `node build-single.js`)
- `worker/` — ה-Backend: `src/worker.js`, `wrangler.toml`, `schema.sql`, `sheets-writeback.gs`, `README.md`
- `sample-inventory.csv` — מלאי לדוגמה
- `test-barcodes.html` — מחולל ברקודים לבדיקה
- `tests/` — בדיקות אוטומטיות (`node tests/run.js`)
- `HANDOFF.md` — מסמך העברת ידע מפורט (ארכיטקטורה, endpoints, פריסה, סודות)
